# Ассистент задач отдела (каркас)

В локальной рабочей папке исходники уже работающего бота не обнаружены; отдельный публичный GitHub-репозиторий найден пустым. Этот проект — автономная Python-основа для его интеграции или запуска как отдельного процесса. В `demo` реальные Graph/Telegram/OneDrive подключения отключены, сетевых вызовов нет.

## Локальный запуск

Требуется Python 3.11+. Скопируйте `.env.example` в `.env` при необходимости, затем:

```sh
python -m assistant init
python -m assistant demo
python -m assistant status
```

База SQLite создаётся по пути `ASSISTANT_DB` (по умолчанию `work/assistant.sqlite3`). Ограничьте доступ к файлу средствами ОС и регулярно делайте резервную копию. Для боевой эксплуатации замените SQLite на управляемую организацией БД с шифрованием и резервированием.

Для постоянного размещения подготовлен Compose:

```sh
cp .env.example .env
# Заполнить .env только локально/из secret manager, затем:
docker compose up -d --build
docker compose logs -f assistant
```

Перед рабочим запуском администратор сам создаёт `.env` на сервере и задаёт `APP_MODE=live`, часовой пояс и секреты. Не отправляйте `.env` в чат, GitHub или этот диалог. Compose сохраняет SQLite в отдельном томе, запускает процесс от непривилегированного пользователя и включает restart policy. Том следует разместить на зашифрованном диске и резервировать вне контейнера. Для более строгого production-хранения замените SQLite и задайте организационное secret manager/KMS.

Команды сотрудника в Telegram: `/today`, `/tasks`, `/status ID СТАТУС`, `/clarify ID текст`, `/block ID причина`, `/help_task ID вопрос`. Для руководителя: `/review`, `/approve ID`, `/assign ID email`, `/report YYYY-MM-DD YYYY-MM-DD`. Кнопки позволяют принять задачу, попросить уточнение, оспорить назначение и подтвердить задачу. Команды требуют предварительной привязки Telegram ID; username не является идентификатором. Демонстрационные записи не являются реальными данными.

Настройка справочника и привязок выполняется локально администратором:

```sh
docker compose exec assistant python -m assistant add-user manager@company.example manager
docker compose exec assistant python -m assistant add-user employee@company.example employee --manager-email manager@company.example
docker compose exec assistant python -m assistant add-mailbox inbox@company.example --manager-email manager@company.example
docker compose exec assistant python -m assistant bind-code manager@company.example
docker compose exec assistant python -m assistant bind-code employee@company.example
```

Сначала внесите руководителя, затем сотрудника с `--manager-email`; укажите руководителя ящика, чтобы очередь писем без исполнителя попадала нужной команде. Передайте выданный одноразовый код лично по проверенному каналу; он действует 15 минут. Сотрудник отправляет боту `/link КОД`. `python -m assistant sync` выполняет один проход. `python -m assistant run` запускает polling Telegram и три ежедневные проверки по `POLL_TIMES` в `ORG_TIMEZONE`.

## Конфигурация и режимы

`APP_MODE=demo` по умолчанию: никаких сетевых запросов. Для работы Telegram задайте `APP_MODE=live` и `TELEGRAM_BOT_TOKEN` в локальном `.env`; для почты дополнительно нужны Microsoft tenant/client ID/secret и перечисленные в базе ящики. `REQUIRE_MANAGER_APPROVAL=true` включает обязательную проверку руководителем перед уведомлением исполнителя. Токен Telegram и Microsoft client secret не передавайте в чате и не коммитьте. Перед постоянным запуском перенесите секреты в секрет-хранилище.

См. `.env.example`. Не задавайте случайные значения организации: расписание, часовой пояс, ящики, сотрудники, папки и роли остаются незаполненными до решения владельца.

## Архитектура и ограничения

- `assistant/db.py`: SQLite, задачи, подтверждённые привязки, отдельный курсор каждого ящика, очередь исходящих событий и аудит.
- `assistant/core.py`: идемпотентный импорт писем; неясный исполнитель или низкая уверенность отправляет запись на уточнение. Письмо рассматривается только как недоверенные данные.
- `assistant/integrations.py`: Telegram Bot API long polling, Microsoft OAuth client credentials + Graph delta, JSON extraction provider. Они активируются только при `APP_MODE=live`.
- `assistant/worker.py`: три ежедневных запуска с часовой зоной и отдельным курсором ящика.
- OneDrive adapter умеет получить метаданные известного Graph item и временный download URL, но поиск по диску, чтение содержимого в ответе, копирование, запись и выдача доступа пока не подключены; вложения писем проверяются по имени/типу/размеру и не скачиваются/не исполняются.

`REQUIRE_MANAGER_APPROVAL=true` по умолчанию: ясная задача сначала попадает руководителю на `/review`; после `/approve ID` сотруднику уходит уведомление. Неясные назначения, низкая уверенность и чувствительные задачи всегда требуют проверки. Создание публичных ссылок запрещено. В журнале не сохраняются тело письма, токены, коды привязки или текст препятствия.

Если Telegram-бот уже работает в другом процессе, не запускайте второй polling экземпляр с тем же токеном. Встройте handlers в текущий процесс либо остановите прежний после переноса команд. Long polling также не работает одновременно с активным webhook.

## Порядок подключения к Microsoft 365

1. Владелец выбирает Azure tenant, почтовые ящики/папки, режим размещения и ответственного администратора.
2. Зарегистрировать приложение Microsoft Entra ID. Текущий фоновой адаптер использует OAuth client credentials и `Mail.Read` Application permission, потому что он должен читать текст писем без присутствия пользователя. `Mail.ReadBasic.All` недостаточен для текста тела. Этот способ требует согласия администратора и может охватить все ящики, если не ограничен.
3. Администратор Exchange должен ограничить доступ приложения только согласованной группой ящиков через Exchange Online Application RBAC и проверить фактический доступ. По документации Microsoft, если ограничение реализуется Application RBAC, не оставляйте одновременно неограниченное Entra application grant для того же разрешения — иначе scoped grant не ограничит широкое разрешение. Для меньшего охвата можно переделать на delegated OAuth, но тогда нужна пользовательская авторизация/обновление токенов и делегированный пользователь должен иметь доступ к каждому ящику.
4. Добавить согласованные ящики в локальную конфигурацию; для каждого стартовая delta-точка ограничена временем добавления, отдельный Graph delta URL сохраняется в БД. Импорт истории отключён.
5. Подключить Telegram токен из секрет-хранилища. Администратор подтверждает привязки Telegram ID одноразовыми кодами вне чата; хранить только хэш кода, срок и факт использования.
6. Настроить подтверждённых руководителей и процедуру одобрения. Затем включать отправку уведомлений для отдельной тестовой группы.
7. Для OneDrive определить конкретную библиотеку/папку и применить ограниченный доступ (предпочтительно SharePoint `Sites.Selected`/site-scoped grant, если это соответствует выбранному хранилищу). На первом этапе достаточно `Files.Read` для чтения разрешённых файлов; добавление/копирование требует отдельного `Files.ReadWrite`/site grant. Ссылки для конкретных лиц потребуют отдельного разрешения и кода; ссылки `anonymous` запрещены. Graph поддерживает уровни `users`, `organization`, `anonymous`; агент не должен использовать широкие уровни по умолчанию.
8. Выбрать ИИ-провайдера и правовое основание передачи почтовых данных. Проверить хранение/регион/retention у поставщика. Извлечение должно проходить JSON-schema validation; назначение, роли и доступы решает программная логика.

Этот каркас не регистрирует приложение, не запрашивает согласие администратора, не создаёт вебхук/публичный endpoint и не разворачивает сервис. Эти действия требуют авторизации владельца.

## Что нужно решить владельцу перед рабочим запуском

1. Точный часовой пояс и три времени запуска; процесс круглосуточного размещения и ответственный.
2. Перечень ящиков, администраторы, папки/правила обработки и разрешён ли импорт истории.
3. Источник справочника сотрудников и способ подтверждения email ↔ Telegram ID; подтверждённые руководители и круг доступа к отчётам.
4. Требуется ли одобрение руководителем до уведомления исполнителя.
5. OneDrive/SharePoint папка, структура, разрешённые форматы/размеры и получатели доступа.
6. Разрешённый ИИ-провайдер и ограничения на передачу почтовых данных.
7. Политика хранения/удаления, резервного копирования и аудита.

## До production

До использования реальных данных нужно встроить код в репозиторий существующего бота (или согласовать его замену), затем выполнить проверку безопасности и эксплуатационную приёмку. OneDrive-копирование/шаринг, анализ вложений, готовый экран администратора и антивирусная проверка пока не реализованы; не включайте в требования к этому каркасу доступ к документам, пока владелец не утвердит расположение и разрешения.
